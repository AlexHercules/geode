# Borges Harness 架构（约束优先）

## 设计哲学：园丁戴镣铐

明确的前提要求：**对 agent 施加更高程度的限制**。所以这不是一个"给模型一支笔让它自由发挥"的 agent，而是一条**确定性流水线**——模型只在流水线的指定工位上做指定动作，每个工位的输出都要过机器校验的 gate，不过就打回重做。自由度是被显式发放的，不是默认拥有的。

原则一句话：**LLM 负责生成，harness 负责裁决；裁决全部确定性。**

## 基座：Git 即故事树

产品的内容模型与 git 同构，直接用 git 做存储与分叉引擎，不自己发明：

| 产品概念 | Git 实现 |
|---|---|
| 一章 | 一个 commit（正文 + canon 增量 原子提交） |
| 一条故事线 | 一个 branch |
| 读者"从第 N 章续写" | 从该章 commit 处 `branch` |
| 第 N 章时点的设定快照 | 该 commit 树里的 `canon/` 目录，天然防剧透 |
| 分支合并（两线汇流） | merge commit |
| 分成结算的创作链 | commit 的祖先链，密码学上不可篡改 |

这一层免费获得：版本完整性、归属证明（谁在哪个点分岔，git 历史即权证）、任意时点快照。平台期再把裸 git 仓库托管到服务端（如 gitaly / 自建对象存储），客户端无感。

## 仓库即一本书

```
book-<id>/
├── canon/                    # 设定即代码 —— 唯一事实源
│   ├── world.md              # 世界观（frontmatter: schema 版本、不可违背的硬设定列表）
│   ├── characters/*.yaml     # 人物卡：性格向量、说话风格、当前状态、关系图
│   ├── timeline.yaml         # 时间线：事件、章节锚点
│   ├── style.md              # 文风指南：视角、时态、禁用词、节奏参数
│   └── ledger.yaml           # 伏笔账本：埋设章 / 状态(open|paid)/ 必须回收期限
├── outline/
│   ├── arc.md                # 卷级大纲
│   └── ch-NNNN.yaml          # 章纲（结构化，过 schema）
├── chapters/
│   └── ch-NNNN.md            # 正文
├── charter.yaml              # 分成章程 + 树规则（建根时锁定）
└── .borges/
    ├── gates.yaml            # 本书的 gate 配置（字数域、审查阈值）
    └── runs/                 # 每次流水线运行的审计日志
```

## 写作流水线（每章一轮）

```
意图输入 ──► ① 章纲生成 ──► ② 草稿 ──► ③ 审查团 ──► ④ 修订 ──► ⑤ 定稿提交
（人类一句话）   [schema gate]            [评分 gate]   (循环≤3)    [checklist gate]
                                            │
                                            └─ ⑥ canon 变更提案 ──► [canon gate] ──► 合并设定增量
```

1. **章纲生成**：输入 = 人类意图 + canon 快照 + 前情摘要。输出必须是过 JSON Schema 的结构化章纲（场景列表、出场人物、推进的伏笔、字数预算）。schema 不过 = 直接拒绝，不进入下一步；
2. **草稿**：只见章纲 + 相关 canon 切片（按需检索，不喂全量——上下文最小权限）；
3. **审查团**：3–4 个并行审稿 agent，各看一个维度，输出结构化评分：
   - canon 一致性（有没有违背硬设定）
   - 人物口吻（对照人物卡逐句抽查对话）
   - 伏笔账本（该回收的回收了吗，新埋的登记了吗）
   - 节奏与文风（对照 style.md）
4. **修订**：低于阈值的维度连同审稿意见打回草稿工位，最多 3 轮，3 轮不过 = 流水线失败、上报人类，**不允许降级通过**；
5. **定稿提交**：机器 checklist（字数域、禁用词扫描、视角一致、敏感内容扫描）全绿才 commit；
6. **canon 变更**：写作 agent **无权直接写 canon/**。章节若改变世界状态（角色死亡、新设定出现），只能提交结构化的 canon change proposal，由独立的 canon gate 校验（与硬设定冲突即拒）后合并。

## 约束清单（更高程度的限制，逐条落地）

| # | 约束 | 实现机制 |
|---|---|---|
| 1 | 结构化输出强制 | 章纲 / 审稿意见 / canon 提案全部 JSON Schema 校验，失败重试，重试有上限 |
| 2 | canon 只读锁 | 文件系统层面：写作工位的 agent 对 canon/ 只有读权限；变更走提案通道 |
| 3 | 硬设定不可违背 | world.md frontmatter 里的硬设定列表是审查团的一票否决项 |
| 4 | 上下文最小权限 | 每个工位只拿到该工位需要的 canon 切片，不给全库 |
| 5 | 预算硬顶 | 每章 token / 成本 / 轮次上限写进 gates.yaml，超限即停，不静默续费 |
| 6 | 不允许降级通过 | gate 失败 3 轮后必须上报人类，harness 无权放水 |
| 7 | 全程审计 | 每次运行的全部 prompt / 输出 / 评分落盘 .borges/runs/，可复盘可回放 |
| 8 | 人类终审位 | charter 可配置：根作者可要求其主线每章人工确认后才发布 |
| 9 | 续写隔离 | 分支续写在独立 worktree 中进行，永远不能改动祖先分支的任何 commit |
| 10 | 发布前置 gate | 平台期：未通过流水线全部 gate 的章节没有发布资格，无后门 |

## Gate 工具层（调研后选型，详见 docs/04-prior-art.md）

四层 gate，确定性在前、便宜在前：

1. **结构 gate**：remark-lint + JSON Schema 校验章纲/frontmatter（毫秒级，零成本）；外加 novelWriter 式标签静态检查（章节引用了不存在的人物/地点 = 直接拒）；
2. **词法 gate**：Vale（YAML+正则自定义规则：禁用词、AI 味词表、视角词）+ textlint（JS 自定义规则：句长分布、排版）；
3. **纠错 gate**：pycorrector 类中文纠错模型，错别字超阈值打回（warning 级，有误报）；
4. **LLM 评审 gate**：审查团基于 promptfoo/deepeval 式 rubric assertion 实现，不自造评测框架。

canon 注入采用 SillyTavern lorebook 机制：canon 条目带 `keys:` 关键词，注入决策由确定性解析器按关键词命中 + token 预算裁剪完成（支持递归激活、sticky 持续在场）——**注入是代码，不是 LLM 的自由检索**，符合最小权限约束。

## 工位编排的技术选型（按阶段）

- **阶段 0（验证流水线）**：Claude Code + 本目录。gates 用上述工具实现为可执行命令；审查团用 subagent 并行跑。先证明"约束流水线写出的章节质量稳定高于裸 prompt"；
- **阶段 1（脱离交互式）**：迁移到 Claude Agent SDK，流水线编排写成确定性代码（TypeScript），gate 全部进程内执行，模型调用是纯函数式的"工位"；
- **阶段 2（平台化）**：流水线跑在服务端队列里，每次续写是一个 job：fork 仓库 → 跑流水线 → gate 全绿 → 发布。读者端只是这个引擎上的一层 UI。
